本轮检查覆盖维护重试与取消、恢复回执、额度接续、权限比较、消息队列、服务重启确认及暂停状态的页面显示。在隔离环境中复现并修复 5 类缺陷；9 个新增回归在修复前全部失败，修复后全部通过。

## 已修复

| 优先级 | 缺陷及影响 | 修复 |
| --- | --- | --- |
| P1 | 用户取消维护时，仍在等待原生状态的“重试”或“检查并继续”可能用旧结果重新激活已取消流程。 | 异步读取返回后重新校验流程版本、服务状态、并发推进及本次启动的接续确认；已取消流程、已收到的回执和新状态不被覆盖。 |
| P2 | 暂停维护会停止自动采样，界面可能长期保留旧连接状态；原生发现暂时遗漏会话时也无法刷新。 | 暂停流程继续进入只读观察，并共用采样节流；保留维护锁，不推进维护或投递消息。 |
| P2 | Codex 额度恢复仍直接比较旧权限指纹，服务更新或客户端重连时会取消本可继续的等待记录。 | 额度恢复采用与维护相同的权限等价判断，记录指纹版本，兼容已有 v2 自动审批别名；保留原请求 ID 和一次发送限制。 |
| P2 | 取消维护后，其“待确认接续”事项仍残留，并可能阻塞后续工作。 | 完成或取消时只移除该维护事项；同时存在的队列确认继续保留，旧弹窗版本失效，暂存消息不被释放。 |
| P2 | 已暂停维护遇到原生权限请求时，页面隐藏真正的暂停原因，错误提示处理权限后会自动继续。 | 暂停原因和对应操作优先显示；正常维护中的权限等待仍显示原有提示。 |

实现位于 `src/maintenance-controller.mjs`、`src/context-monitor.mjs`、`src/quota-recovery.mjs`、`src/restart-confirmation.mjs`、`src/management-store.mjs` 与 `public/maintenance-view.mjs`。

## 后续优化建议

1. **为暂停原因增加稳定错误码。** 当前 `maintenance-recovery.mjs`、`checkpoint-service.mjs` 和 `maintenance-view.mjs` 都依赖中文文案匹配。改为错误码决定恢复条件与操作，文案只负责显示，可降低修改提示文字时误改流程行为的风险。
2. **显示设置前后差异和采样时间。** 当前诊断面板主要给出通用原因及当前模型；增加维护触发时与当前的模型、思考强度、权限模式，以及状态更新时间，用户可直接区分真实变更、信息缺失与过期快照。仅展示必要元数据。
3. **为原生协议适配建立固定回放样例。** 将已脱敏的初始化缺省、权限别名转换和重连时序作为版本化样例，升级 Codex、Claude 或 OpenCode 后先回放，再验证真实只读状态。已有确定性测试可作为基础，不需要运行真实业务任务。

这些建议尚未实施；本轮改动集中在已复现的 5 类缺陷。
